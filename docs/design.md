# 设计与协议

## 传输与组帧

`POST /api/ingest/{source}`，`Content-Type: application/octet-stream`。
正文是原始字节，可为半帧、多帧、噪声或其组合；不是 JSON，也不是十六进制字符串。
来源名称限制为 1–32 个英文字母、数字、连字符或下划线。

一个 HTTP 请求本身具有消息边界，但演示刻意忽略它作为业务帧边界：
每个来源在多次请求之间保留解析状态，模拟驱动任意分块交付 UART 字节的行为。
当前 HTTP 适配不是实际 UART 驱动，也不能验证波特率、中断或 DMA 行为。

线协议复用 serial-frame：

```text
AA 55 | LEN:u8 | PAYLOAD | CRC16/MODBUS:u16LE
```

CRC 覆盖 LEN 和 PAYLOAD。遥测 v1 的 PAYLOAD 固定 11 字节：

| 字段 | 类型 / 偏移 | 含义 |
|---|---|---|
| version | u8 / 0 | 当前为 1 |
| device | u16LE / 1 | 1–64 |
| sequence | u32LE / 3 | 调用方序列号，不作去重键 |
| temperature | i16LE / 7 | 摄氏温度 ×100，−5000–15000 |
| humidity | u16LE / 9 | 相对湿度 ×100，0–10000 |

完整遥测帧为 16 字节。C++ 按字节读取字段，不依赖结构体填充、主机大小端或未对齐访问。
接收时间由网关写入，记录 Unix 毫秒，不包含设备自身时钟。

## 并发与所有权

- cpp-httplib 使用阻塞 Socket I/O；配置 4 个工作线程和最多 64 个排队请求任务。
  HTTP 任务队列满时由库关闭/拒绝连接，和业务存储队列的 HTTP 429 不是同一机制。
- 一个网关互斥锁保护所有来源解析器、样本队列、计数器和事件环。
  不同来源可并发提交，但解析阶段串行执行；不宣称多核并行解析或无锁设计。
- 单个来源必须按序提交请求。相同来源并发请求的先后顺序由获得锁的顺序决定，
  无法自动重建调用方原始字节顺序。
- 解析回调立即把数值字段复制到 Reading，绝不保留 C 解析器内部 payload 指针。
- 存储队列达到容量后丢弃最新样本，避免无界增长。默认容量 1,024，最多 100,000。
  C++ 队列、容器和第三方库使用动态内存；只有 C99 帧核心使用固定缓冲区。
- 存储线程先出队并释放网关锁，再调用 SQLite；查询和写入由单独数据库锁串行化。
  不在持有数据库锁时获取网关锁，防止形成循环锁依赖。
- 最近事件保存最后 50 条。来源数最多 32，设备编号最多 64；数据库大小不受此限制。

## 时间与故障

组帧使用 `steady_clock` 派生的 uint32 毫秒 tick，避免系统日历时间调整影响超时。
记录和显示使用 `system_clock`，因此更改系统时钟会影响接收时间与在线判断。

超时从候选帧首个 AA 起算，不因新字节延长，是整帧组装期限，不是字节间空闲期限。
没有新输入时，存储线程的等待循环也会检查残帧；检查周期目标为 25 ms，
但单次数据库写入、人工测试延迟和线程调度均可能使实际回收晚于这个周期。
特别是 SQLite 繁忙时会等待最多 2 秒，因此这不是硬实时超时系统。

写入失败计入 `storage_errors` 并保留事件，本版不自动重试。
队列拥塞、存储错误、CRC 错误和 schema 错误分开统计，避免把“解析成功”误当成“已保存”。

## 持久化语义

SQLite WAL + synchronous=FULL，每条样本单独提交；这里优先采用简单、可解释的提交语义。
数据库 API 用 RAII 回收 prepared statement，参数使用绑定而非拼接 SQL。
读写共享一个连接和互斥锁，长查询会影响写入速度；尚未使用读连接池或批量事务。

HTTP 202 仅确认数据已入队，数据库真正提交后 `stored` 才增加。
正常 SIGINT/SIGTERM 退出时会停止 HTTP 服务并排空已有样本队列。
Windows 强制终止进程、系统掉电或崩溃不保证排空队列；已提交记录的恢复交给 SQLite，
不把它推广为所有硬件和文件系统上的绝对掉电保证。

`accepted = stored + storage_errors + queue_depth + in_flight` 适用于同一时刻的进程内计数，
其中 in_flight 为已经出队、正在写入的至多 1 条样本；API 统计与数据库总数不是跨锁原子快照。
历史总数包含之前进程保存的记录，不能与本次进程 stored 直接等同。

## API

| 方法 / 路径 | 返回 |
|---|---|
| GET /api/health | 服务版本及存活状态 |
| POST /api/ingest/{source} | frames、accepted、dropped、invalid_payloads、pending |
| GET /api/stats | 本次进程计数、队列状态、历史总数、最近事件 |
| GET /api/devices | 每个设备最后一条已存储样本及在线判断 |
| GET /api/history?device=1&limit=120 | 最近 limit 条，按接收记录 id 升序返回；上限 5000 |
| GET /api/export.csv?device=1 | 此设备最近至多 5000 条样本 |

状态码：202 入队处理完成；400 参数错误；413 正文过大；415 Content-Type 错误；
429 来源数超限或部分样本因队列满而丢弃；500 存储查询等内部异常。

历史记录以自增 id 表示接收顺序，不按设备序列号排序；同一设备重启后序列号回到 1 仍会保存。
